Developer handoff · review copy

Cuebox. design pack

A brief for implementing the locked Cuebox UI and motion in BlackLodgeLabs/cuebox. This copy is for Craig to review first. Nothing in this pack has been sent to Developer.

Please work from this pack, not from Figma — the Figma file is behind. Trust the locked values in the tables below, and the slider defaults in the HTML testers. Reference videos in this pack were recorded at those locked values (the Recommendation shuffle is the constant 420px/s cruise, not the earlier 260px/s recording).

What’s in the pack

  • README.md — the full brief for Developer (this page is a readable version of it).
  • tokens/ — tokens.css and tokens.json for colour, type, radii, spacing and motion.
  • screens/ — final phone PNGs and the overview sheet.
  • motion/ — reference MP4s and offline HTML testers, with art and fonts included. Slider defaults have been set to the locked values.
  • CHECKLIST.md — acceptance criteria per screen.
  • draft-message-to-developer.txt — a short unsent note you can use when you’re ready to share the pack.

Suggested order of work: tokens and the app shell, then shared overlays (sheets, toasts, search, dialogs), then Home and Search, Watchlist (including infinite scroll), Film detail, Review, Recommendation, History, Settings, then Sync and Import (shared defaults only), and a reduced-motion pass.

Type: Big Shoulders for titles and the wordmark, Archivo for UI, IBM Plex Mono for metadata. Do not use Inter. Radius 12px default, 8px tiles, 16px sheets. Spacing 4 / 8 / 16 / 24 / 32 / 48. Wordmark: Cue amber, box and the full stop teal. Review stars and watchlist rating badges are amber; teal is used for Saved, links and the active tab, not for stars.

Shared easing: cubic-bezier(0.16, 1, 0.3, 1). Reduced motion: appear at once, or a 300ms fade, with no travel, scale or glow unless a screen’s lock says otherwise.

Recommended libraries to add and restyle (they are not installed on main yet): shadcn/Radix, Vaul for sheets, Sonner for toasts, cmdk for search, AlertDialog for confirms, NumberFlow for rolling figures, Framer Motion for movement.

Locked screens

Phone crop, 390 × 844. The surprise, search-added, More sheet and My services images come from the earlier locked screen set, to show patterns that were not re-exported on the current-state contact sheet.

History is a ticket-stub list of past recommendation nights, under More. Tapping a ticket opens the locked programme layout titled with the date (for example “Sat 14 Nov”), not the old three-stage ceremony, and does not replay the shuffle. To remove a night, swipe the ticket left to reveal Remove, or long-press it — both go through the confirm box. A normal tap only shrinks the ticket slightly; there is no amber on press. Sync and Import, also under More, had no design pass: they use the shared foundations and app-wide motion defaults, and are a placeholder to revisit if the app is ever opened to other users.

What the locked screens show

Where an earlier line in a brief disagreed with these screens, the screens and the locked notes win. The full README.md has the same facts, written out in full.

  • Tab bar: four tabs — Home, Watchlist, Recommend, More. Recommend starts the questionnaire and shows the programme. History sits under More.
  • Watchlist pills: Unwatched, Watched, Archived. There is no All pill. Pills have no counts; the total under the title is for the current view (for example “239 unwatched”).
  • Stars are amber. The teal “Saved” label is not a star colour. Create-sheet star glow is on at 35%.
  • Home: a Search films field in the header opens the cmdk card. Under today’s feature: Where to watch (amber), Get a pick for tonight (teal-outline, starts the 11-step questionnaire), and Surprise me (smaller teal text, a Vaul sheet).
  • Questionnaire: 11 steps, one at a time. The pack shows 1 of 11 (genres), 2 of 11 (runtime) and 11 of 11 (notes), then the shuffle, then the programme.
  • Create review: a star tap saves the watch at once. Date and note then appear, both optional, with no Save button (the note autosaves on blur). Edit review uses Save changes.
  • Trailer (bottom bar) and Close to this on your watchlist (You tab, unwatched films only) are in scope.
  • The My services PNG still says “It never hides a film.” That copy is stale — see open questions below.

Behaviour changes and API notes

  • Infinite scroll replaces any next-page control. GET /films already paginates with limit, offset and has_more. Call it with limit=18 (the API default is 20).
  • Pills have no counts. The total under the title is the current query’s pagination.total.
  • Pills are Unwatched (active), Watched, and Archived (archived). There is no All pill. Unwatched in the UI is API status active.
  • Needs to be agreed, because they were not on the list endpoint in the copy that was checked: filter “On my services”, filter by genre or runtime, and sort by runtime or rating. Date added, title and year already exist.
  • A manual watch must be allowed to have no date. Do not write the Letterboxd sentinel 1984-09-28 onto a new or edited manual watch.
  • Deleting a finalized watch may need a new endpoint (only a pending-draft delete was found). Deleting a film’s only watch must not change its status — it stays watched.
  • Create review: a star tap saves the watch; date and note then appear and have no Save button (note autosaves on blur). Edit review uses Save changes.
  • History uses GET /recommendations with limit=10 and infinite scroll. Opening /history/{id} must show the locked dated programme, not the old ceremony, and must not replay the shuffle. Remove is swipe-left or long-press, both through the confirm box, then DELETE /recommendations/{session_id}.
  • Sync and Import had no design pass — use shared foundations and app-wide motion defaults.

Open questions for Craig

These were not locked. The recommendations are for Craig to confirm; do not treat them as decided.

  • My services wording. Keep both behaviours (sorts Where to watch; the Watchlist filter can hide films) and change the line to: “Used to sort Where to watch, so your subscriptions come first, and by the On my services filter on the Watchlist. You can change this whenever you like.” The PNG is stale until that copy is confirmed.
  • Runtime filter buckets. Use Short ≤ 90 minutes, Medium 91–150, Long over 150, matching the chips already on the Filter sheet, unless Craig prefers different cuts.
  • Sort by rating. On Watched, sort by the user’s own rating; on Unwatched and Archived, sort by TMDB.
  • How Home rails are filled. Today’s feature is one watchlist film, once a day. For the named rails, pick from the watchlist using genre, mood and runtime, and allow them to refresh over time.

Other gaps

  • Sync and Import (under More) had no design pass. Use the shared foundations and app-wide motion defaults, and treat them as a placeholder to revisit if the app is ever opened to other users.
  • Archive / Remove on a film (the More sheet on Film detail) have no confirmation in the locked mocks. This is separate from History, where Remove does go through the confirm box.
  • No undo on toasts. The date picker can stay native.
  • An exact minimum-cruise time for Recommendation was not locked.
  • Some mock posters, scores and trailers are stand-ins. Use real data in the app.
  • Figma is not up to date and is not the source of truth.

How to try the mocks

Unzip the pack and open each HTML file from inside its motion/… folder, in a desktop browser, so the images and fonts load. There is a short README.txt in each folder.
